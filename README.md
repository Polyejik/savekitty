# Save Kitty / Спаси Пушка

Educational long-division game, RU/EN. The readable `index.html` is the single game entrypoint for local development and GitHub Pages.

Build: `python3 scripts/build_site.py`. Serve the generated `public/` directory. GitHub Actions runs this exact build, adding content hashes to active scripts. Historical `_parts/` and older script versions are not shipped.

A full game writes one result to `savekitty_analytics_v1` in localStorage after the ninth lock. `supabase-sync-v2.js` sends pending results to the Worker with a persistent `completion_id`, so retries are idempotent. The Hall of Fame reads `/leaderboard`: the ten fastest qualifying results across the database, one best result per player ID. Games below 45 seconds are excluded; the donation daily limit does not prevent ranking. Player identity is per browser installation, without a user account. The sponsor dashboard reads actual aggregate data from the Worker; it never substitutes demo values on failure.

Worker: `worker/src/index.js`, deployment configuration: `worker/wrangler.jsonc`. Pages and Worker are separate deployments; changing only Pages cannot fix API code.

Invitations are server-only: the Worker creates/hardens `game_challenges` atomically with RLS enabled and no table or column privileges for `PUBLIC`, `anon` or `authenticated`. Existing records and the server role's access are preserved. The same SQL is available in `supabase/migrations/20260915_protect_game_challenges.sql`. The live database security workflow waits for the Worker deployment, applies the idempotent bootstrap through the existing dashboard route, and verifies RLS and privileges from the live PostgreSQL catalog through `/database-security` (read-only metadata, no player records). It also attempts anonymous Supabase REST reads; an unresolvable legacy REST hostname is reported explicitly as an unavailable external check. This workflow does not submit game results.

The dashboard distinguishes all unique saved games from donation-eligible games, daily-limit runs, fast tests and historical duplicate requests. Actual server receipts are stored in `savekitty_sync_receipts_v1`; opening the game or dashboard on the original device retries unacknowledged UUID results. A historical non-UUID sent marker is not blindly replayed. CSV/print exports reflect loaded data, never invented transfers.

`dashboard/partners.html` hosts private fund/sponsor rooms. The organizer creates a room and saves the organizer link, then manually shares separate role links. Fund actions: need, receipt, report, message. Sponsor actions: pledge, transfer, message. A pledge references a need; a transfer references a pledge; a receipt references a transfer. Cumulative amounts cannot exceed the referenced amount. Events are append-only and retries use an idempotency UUID. All participants see their room history and CSV export; payments themselves happen outside the service. Organization affiliation is not verified. Keep recipient personal data out of these rooms.

Room links contain a 256-bit secret in the URL fragment, immediately removed from the address bar and retained only in sessionStorage. The Worker receives it as a Bearer header and stores SHA-256 digests, never raw tokens. An organizer can revoke/replace fund or sponsor invitations. Both new tables are created with RLS and public privileges revoked in one atomic bootstrap, and the live catalog check covers them. Creation is limited to five rooms per IP per UTC day, and each room to 1,000 entries. Do not create production test rooms or financial entries during automated verification.

Regression checks: `npm ci --prefix tests`, then `QA_MODULES="$PWD/tests/node_modules" node tests/regression.cjs` and `QA_MODULES="$PWD/tests/node_modules" node tests/dashboard-sql.cjs`. The Pages workflow runs the full test list, including real PostgreSQL execution with PGlite, all role/room boundaries and invitation revocation, offline sync recovery, dashboard/room UI and global leaderboard. No test completions or financial entries are submitted to production.
